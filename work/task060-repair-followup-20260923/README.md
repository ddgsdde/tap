## 成功修复是怎样得到的

成功路径是**参考电路重建**，不是 SAT 搜到了一个新最优解：先合并重复 NAND，以完整真值签名识别可复用信号，再用已验证参考电路重建输出位 4 的逻辑，保持其他七个输出的函数不变。最后重新枚举全部 256 组输入，与整数 `A*B` 直接比较。

这种恢复需要回到 117 门。因此，“恢复正确性”和“在 116 门内修好并刷新成绩”是两个不同目标；本轮只完成了前者。

## 独立验证及复现

`repair_and_verify.py` 只依赖 Python 标准库。常量 0/1 和八个输入在深度零，最后八个物理 NAND 门按低位到高位输出。验证时不信任 JSON 中已有的验证字段。

```bash
cd work/task060-repair-followup-20260923
python3 repair_and_verify.py --verify repaired_117_VERIFIED.json
python3 repair_and_verify.py --verify near_114_NOT_VALID.json
```

第二条命令应返回退出码 1，并显示 `7×7` 反例。

在完整仓库中重现正确性恢复：

```bash
python3 repair_and_verify.py --output reproduced_117.json
```

默认读取上一轮目录 `../task060-mul4-20260923/` 中的 `near_miss_116_NOT_VALID.json` 和 `best_known_117.json`。也可用 `--near` 与 `--reference` 指定路径。脚本会先验证参考电路；不会把错误网表当成正确参考。
