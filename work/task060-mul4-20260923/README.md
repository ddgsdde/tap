## 独立验证

`verify.py` 只使用 Python 标准库，逐组计算全部 `16 × 16 = 256` 个输入。它直接比较 `A*B`，不信任网表附带的验证字段。输入 word 的低四位为 A、高四位为 B；常量 0/1 和八个输入在深度零；最后八个物理 NAND 门按低位到高位作为输出。

```bash
cd work/task060-mul4-20260923
python3 verify.py best_known_117.json
python3 verify.py near_miss_116_NOT_VALID.json
```

第二条命令**应返回退出码 1**，并打印 7×7 反例。这是正确拒绝错误电路，不是工具故障。

生成仓库现有精确综合器兼容的、经过验证的 reference：

```bash
python3 verify.py best_known_117.json --reference-out best_known_117.reference.json
```

**不要把错误的 116 门网表直接作为 exact_nand.py 的 reference 目标。** 那样会把错误函数当成目标。这里的导出器会拒绝为错误网表生成 reference。

## 继续修复 116 门检查点

`window_repair.py` 是已做 SAT 解码和全输入校验自测的局部修复入口。使用系统 `libz3` 共享库；本次运行版本为 `4.13.3.0`，不依赖 Python 的 z3py 包。示例：

```bash
python3 window_repair.py \
  --input near_miss_116_NOT_VALID.json \
  --window 8 --seconds 600 --timeout 10000 --seed 6061 \
  > continuation.log 2>&1
```

`--timeout` 为每个查询的毫秒上限；总预算可能因最后一个查询而略超出。窗口外连线固定，窗口内可重选 NAND 输入，并采用不增加各门既有深度的限制。每个查询约束全部 256 组输入；只有通过独立标量验证、且成本低于 59,904 的结果才写入 `candidate_116_verified.json`。脚本不提交交易。

局部 `unsat` 只排除当前冻结边界、接线顺序及深度限制下的窗口；**不能推出整个 116 门搜索空间无解**。`unknown` 或超时也不能当作 `unsat`。
